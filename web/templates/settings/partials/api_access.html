Minimum gap between runs started through the API. Calls inside the gap, or while a run is going, are merged into one follow-up run rather than dropped. 0 turns the gap off.
Examples: curl, Tautulli, Home Assistant
Replace YOUR_API_KEY with the key above. If you reach PlexCache through a different address, adjust the URL.
# Start a run (202: started or queued; 409: maintenance or a CLI run is in progress)
curl -X POST -H "X-Api-Key: YOUR_API_KEY" {{ api_base_url }}/api/run

# Status, including any queued run
curl -H "X-Api-Key: YOUR_API_KEY" {{ api_base_url }}/api/status

# Stop the current run after the file in progress, and drop a queued run
curl -X POST -H "X-Api-Key: YOUR_API_KEY" {{ api_base_url }}/api/stop
Tautulli: Settings → Notification Agents → Add → Webhook. Webhook URL {{ api_base_url }}/api/run, method POST. Under Triggers tick Playback Stop. Under Data → Playback Stop → JSON Headers:
{"X-Api-Key": "YOUR_API_KEY"}
Home Assistant: in configuration.yaml, then call rest_command.plexcache_run from an automation:
rest_command:
  plexcache_run:
    url: "{{ api_base_url }}/api/run"
    method: POST
    headers:
      X-Api-Key: "YOUR_API_KEY"
